## Cause

Un conteneur LXC sans serveur DNS déclaré reçoit celui du nœud : Proxmox recopie le `resolv.conf` du nœud entre les marqueurs `# --- BEGIN PVE ---`.

Or `pve-macmini` avait été enrôlé dans le tailnet avant ims-ops, avec le DNS du tailnet activé (`100.100.100.100`, MagicDNS), contrairement à l'inventaire (`tailscale_accept_dns: false`). Le rôle `tailscale` ne modifie jamais un hôte déjà connecté, et `just audit` affichait le réglage sans le comparer à l'inventaire : l'écart était passé inaperçu.

Dans le worker, Tailscale tourne sans le DNS du tailnet : personne n'y répond à `100.100.100.100`. Tant que le worker recevait son DNS du DHCP, l'héritage ne jouait pas ; le passage en IP fixe l'a révélé.

## Correction

Sur `pve-macmini` :

```bash
sudo tailscale set --accept-dns=false          # resolv.conf du nœud : 192.168.1.254
sudo pct set 105 -nameserver 192.168.1.254     # DNS du worker indépendant du nœud
sudo pct reboot 105
```

Puis `just setup ims-coolify-worker base`.

## Leçons

- Une IP fixe se déclare avec son serveur DNS : `pct set <vmid> -nameserver …` en même temps que `-net0`.
- Un réglage affiché par l'audit sans être comparé à l'inventaire n'est pas contrôlé.
