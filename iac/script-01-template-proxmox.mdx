## Objectif

Ce script crée sur `pve` le template de VM Ubuntu 24.04 (cloud image, VMID 9000). Chaque VM clonée depuis ce template démarre avec le compte `cmolotkoff`, ta clé SSH, l'agent QEMU et Tailscale enregistré sur Headscale.

| Élément | Valeur |
|---|---|
| **Outil** | Script shell, exécuté sur `pve` via le Makefile |
| **Fichiers** | `lots/01-proxmox-template/create-template.sh`, `vendor-data.yaml` |
| **Commandes** | `make template`, `make template-snippet` |

---

## Fonctionnement

| Fichier | Rôle |
|---|---|
| `create-template.sh` | Télécharge la cloud image, crée la VM 9000 (2 vCPU, 2 Go, `local-lvm`), configure Cloud-Init (`cmolotkoff`, clé SSH, DHCP, domaine `ims-world.fr`), puis la convertit en template |
| `vendor-data.yaml` | Snippet Cloud-Init exécuté au premier démarrage d'un clone : installe `qemu-guest-agent` et Tailscale, puis enregistre la VM sur Headscale (user `infra`) |

### Pourquoi vendor-data et pas user-data

`--cicustom "user=…"` écrase les meta-data générées par Proxmox : le hostname, l'utilisateur et sudo sont perdus. `--cicustom "vendor=…"` s'ajoute à ces meta-data. Le snippet ne fait donc que ce que Proxmox ne fait pas : Tailscale et l'agent QEMU.

### Protection contre la destruction accidentelle

Si le template 9000 existe déjà, le script affiche son nom et demande de taper `9000` pour confirmer. `FORCE=1` permet de sauter la confirmation dans un usage scripté.

## Procédure

<Steps>
  <Step title="Créer le template">
    ```bash
    make template
    ```
    Le Makefile copie le script et ta clé publique sur `pve`, puis lance le script avec sudo.
  </Step>

  <Step title="Installer le snippet Cloud-Init">
    Enregistre la clé de pré-authentification Headscale dans `secrets/headscale-preauth.key`, puis :
    ```bash
    make template-snippet
    ```
    Le snippet est écrit dans `/var/lib/vz/snippets/vendor-data.yaml` sur `pve`, en mode `600`.
  </Step>

  <Step title="Cloner une VM">
    Sur `pve` :
    ```bash
    sudo qm clone 9000 <VMID> --name "<nom>" --full --storage local-lvm
    sudo qm set <VMID> --cicustom "vendor=local:snippets/vendor-data.yaml"
    sudo qm set <VMID> --memory 2048 --cores 2
    sudo qm start <VMID>
    ```
  </Step>

  <Step title="Durcir la VM">
    Ajoute la VM au groupe `[vms]` de `ansible/inventory.ini`, puis applique le [script 04](/iac/script-04-securite-ssh).
  </Step>
</Steps>

## Vérification

- `sudo qm config 9000 | grep template` affiche `template: 1`.
- Une minute après le démarrage d'un clone, la VM apparaît dans Headplane.
- Sur le clone, `systemctl is-active qemu-guest-agent` affiche `active`.

---

## Dépannage

| Symptôme | Cause | Correction |
|---|---|---|
| Le clone n'apparaît pas dans Headscale | Clé pré-auth expirée ou snippet absent | Régénère la clé dans Headplane, puis `make template-snippet` |
| Hostname `ubuntu` sur le clone | `--cicustom user=` utilisé | Recrée le clone avec `vendor=` |
| `secrets/headscale-preauth.key` manquant | Fichier absent | Crée la clé dans Headplane et enregistre-la dans `secrets/` |
