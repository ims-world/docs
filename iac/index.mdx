## Le dépôt IMS-INFRA

Le dépôt IMS-INFRA regroupe tous les scripts et playbooks d'administration du homelab. Il est organisé par script et composant fonctionnel : chaque brique possède son dossier, son `README.md` explicatif et ses commandes dédiées.

## Principes

### Un seul point d'entrée : le Makefile

Chaque action a une cible make. Tu n'as pas à retenir les commandes Ansible complexes.

```bash
make help               # liste toutes les commandes, groupées par script
make ping               # connexion + sudo sur tous les hôtes
make termix-check HOST=ims-nas
make termix-apply HOST=ims-nas
```

`HOST=` limite une commande à un seul hôte. Les commandes destructrices exigent une confirmation explicite (`CONFIRM=oui`).

### Script ou Ansible

| Situation | Outil | Exemple |
|---|---|---|
| Action ponctuelle sur une seule machine | Script shell | Créer le template, préparer un nouveau LXC |
| État à maintenir sur plusieurs hôtes | Ansible | Compte Termix, durcissement SSH |

### Connexion d'Ansible

| Règle | Détail |
|---|---|
| Compte | `cmolotkoff` + sudo. Jamais root direct. |
| Hôtes du tailnet | Joints par leur IP Tailscale : Ansible fonctionne depuis n'importe où |
| LXC sans Tailscale | IP LAN + rebond par pve (ProxyJump) |
| Clés d'hôte | `host_key_checking` activé : chaque clé est enregistrée avant le premier passage |

### Qualité

- Toute modification se simule avec `--check --diff` (cibles `*-check`) avant d'être appliquée.
- `make lint` (`ansible-lint`, profil production) doit passer.
- Une variable obligatoire absente fait échouer le rôle : jamais de valeur factice.
- Aucun secret dans le dépôt : `secrets/` (`.gitignore`) ou Vaultwarden.

```text
│   ├── 03-termix/           # README.md

│   ├── ansible.cfg
│   ├── inventory.ini
│   ├── group_vars/all.yml
│   ├── playbooks/          # un playbook par composant
│   └── roles/
└── secrets/                # gitignored
```

## Ajouter un script ou playbook

1. Crée `lots/NN-<nom>/README.md` sur le modèle des composants existants : objectif, prérequis, commandes, variables, vérification, dépannage.
2. Ajoute les cibles `<nom>-check` et `<nom>-apply` au Makefile, sous un titre `##@ Script NN`.
3. Ajoute la ligne au sommaire du `README.md` racine, avec son statut.
4. Crée la page Mintlify correspondante dans ce groupe et ajoute-la au sommaire ci-dessus.

Voir aussi l'[ADR-011 — Organisation d'IMS-INFRA par lots](/history/adr/adr-011-organisation-ims-infra-par-lots).
