## Objectif

Ansible se connecte à tous les hôtes avec le compte `cmolotkoff` et passe root par sudo, jamais en root direct. Ce script crée ce compte dans les conteneurs LXC, qui ne passent pas par Cloud-Init.

| Type d'hôte | Origine du compte cmolotkoff |
|---|---|
| VM issue du template | Cloud-Init ([Script 01](/iac/script-01-template-proxmox)) |
| Nœud Proxmox | Créé lors de l'installation |
| LXC | Ce script |

| Élément | Valeur |
|---|---|
| **Outil** | Script shell, exécuté sur le nœud Proxmox via `pct exec` |
| **Fichier** | `lots/02-acces-admin/bootstrap-lxc-admin.sh` |
| **Commande** | `make admin-bootstrap CT=<id> NODE=cmolotkoff@<nœud>` |
| **Statut** | Validé en production le 22/10/2026 sur les trois conteneurs du parc |

---

## Fonctionnement

Le script s'exécute sur le nœud qui héberge le conteneur et entre dans le conteneur avec `pct exec`. Il ne demande donc aucun accès SSH préalable au LXC.

Dans le conteneur, il :
- installe `sudo` et `python3` s'ils manquent (Ansible en a besoin) ;
- crée `cmolotkoff` s'il n'existe pas ;
- ajoute ta clé publique (`~/.ssh/id_rsa.pub`) à son `authorized_keys`, sans doublon ;
- pose `/etc/sudoers.d/cmolotkoff` (`NOPASSWD: ALL`), validé par `visudo`.

Le script est relançable sans effet de bord.

<Info>
  Ce choix d'un script plutôt qu'Ansible est volontaire : l'action est ponctuelle (une fois par conteneur) et elle est justement le prérequis qui permet ensuite à Ansible de se connecter.
</Info>

<Warning>
  **Cas particulier LXC 100 (NAS) — Règle UID 1000 Samba** :
  Sur le NAS, le compte `cmolotkoff` existait déjà pour Samba avec l'UID 1000. Le shell a été passé de `/sbin/nologin` à `/bin/bash` et le mot de passe système a été verrouillé (`passwd -l`). **Ne jamais modifier son UID (1000) ni supprimer ce compte** pour ne pas corrompre les droits POSIX sur le pool MergerFS.
</Warning>

## Procédure

| Conteneur | Commande | Statut au 22/10/2026 |
|---|---|---|
| LXC 100 — NAS | `make admin-bootstrap CT=100 NODE=cmolotkoff@100.64.0.9` | ✅ Configuré (Samba UID 1000 + SSH) |
| LXC 103 — PBS | `make admin-bootstrap CT=103 NODE=cmolotkoff@100.64.0.9` | ✅ Réparé (clé SSH rétablie) |
| LXC 105 — worker | `make admin-bootstrap CT=105 NODE=cmolotkoff@100.64.0.6` | ✅ Créé & opérationnel |

`NODE` est le nœud qui héberge le conteneur : `pct` n'agit que sur les conteneurs locaux. Si la commande répond `does not exist`, relance-la sur l'autre nœud.

Chaque exécution se termine par `OK — cmolotkoff prêt sur <hostname>`.

### Ajouter un nouveau LXC au parc

<Steps>
  <Step title="Créer le compte">
    ```bash
    make admin-bootstrap CT=<id> NODE=cmolotkoff@<nœud>
    ```
  </Step>

  <Step title="Déclarer l'hôte">
    Ajoute une ligne dans `ansible/inventory.ini` : IP LAN + `ansible_ssh_common_args='-o ProxyJump=cmolotkoff@100.64.0.9'` si le conteneur n'a pas Tailscale.
  </Step>

  <Step title="Enregistrer sa clé d'hôte">
    ```bash
    ssh cmolotkoff@100.64.0.9 'ssh-keyscan -t ed25519 192.168.1.X' >> ~/.ssh/known_hosts
    ```
  </Step>

  <Step title="Vérifier">
    `make ping HOST=<hôte>` doit répondre `root`.
  </Step>
</Steps>

## Dépannage

| Symptôme | Cause | Correction |
|---|---|---|
| CT `<id>` non démarré | Conteneur arrêté | `sudo pct start <id>` sur le nœud |
| `Configuration file ... does not exist` | Mauvais nœud | Relance avec l'autre `NODE` |
| `make ping : Permission denied (publickey)` | Mauvaise clé publique déposée | Vérifie `SSH_PUB` (par défaut `~/.ssh/id_rsa.pub`) et relance |
| `make ping : Host key verification failed` | Clé d'hôte inconnue | Refais l'étape d'enregistrement de la clé d'hôte |
